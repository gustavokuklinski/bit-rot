# Contributing to Bit Rot

First off, thank you for considering contributing to this project!
We welcome community contributions via **Pull Requests** (PRs) and **Issues**. 

Please read this document carefully to ensure a smooth collaboration process.

---

## 1. Fork & Pull Request Workflow

Since our license permits forking for contribution purposes, please follow this workflow:

1. **Fork** the repository to your own GitHub account.
2. **Clone** your fork locally:
   ```bash
   git clone https://github.com/gustavokuklinski/bitrot.git
   ```
3. **Create a new branch** for your feature or bugfix:
   ```bash
   git checkout -b feature/your-feature-name
   ```
   - Use `feature/` for new features.
   - Use `bugfix/` for bug fixes.
   - Use `docs/` for documentation updates.
4. Make your changes and **commit** them (see commit message guidelines below).
5. **Push** your branch to your fork.
6. Open a **Pull Request** against the `main` (or `develop`) branch of this original repository.

---

## 2. Commit Message Guidelines

Write clear, concise commit messages in the imperative tense:

- ✅ `Add user authentication middleware`
- ✅ `Fix null pointer exception in parser`
- ❌ `Updated stuff`

If your commit includes AI-generated code, you **must** include an AI tag in the commit body (see Section 4).

---

## 3. Coding Standards

To maintain consistency:

- **Linting**: Please run the project's linter/formatting tool before submitting (e.g., `prettier`, `black`, `ruff`, `gofmt` — adjust to your tech stack).
- **Comments**: Document complex logic. If AI wrote it, verify that the comments are accurate.
- **Testing**: Where applicable, include unit tests for new functionality.

---

## 4. AI Contribution Tagging Policy (Mandatory)

**Transparency is key.** If you used any Generative AI (LLM) to assist in writing code, documentation, or tests included in your PR, you **must** tag it clearly.

### Tag Format

Place this in your **PR description** and in the **commit body**:

```text
[AI_Model] [Category] - Brief description of generated content
```

### Allowed AI Models

Please use the exact model names from our [AI Disclosure](AI_DISCLOSURE.md):

- `gemma3:31B`
- `Gemini 2.5 Pro`
- `Gemini 3.1 Pro`
- `Qwen3.5`
- `ChatGPT-5o`
- `DeepSeek-R1`

### Allowed Categories

- `[Code]` – For any functional code, algorithms, or boilerplate.
- `[Fix]` – For bug fixes suggested or generated by AI.
- `[Refactor]` – For code restructuring.
- `[Test]` – For unit or integration tests.
- `[Doc]` – For documentation updates, comments, or README changes.

### Examples

**PR Description:**
```text
## AI Contribution Tag
[DeepSeek-R1] [Code] - Generated the data validation helper functions.
[Gemini 2.5 Pro] [Fix] - Provided fix for edge case in sorting algorithm.
```

**Commit Body:**
```text
Add input sanitization utility

[ChatGPT-5o] [Code] - Generated the initial regex patterns for sanitization.
```

> **Note:** If the entire PR is 100% human-written, simply state `[Human]` or leave the AI section blank.

---

## 5. List of Changes

To help us review your PR quickly, please provide a **detailed list of changes** in the PR description. Use bullet points and keep it grouped:

```markdown
## List of Changes
- **Added**: New `AuthService` class for JWT handling.
- **Modified**: Updated `database.js` to use connection pooling.
- **Removed**: Deprecated `old_parser.py`.
- **Fixed**: Resolved memory leak in event loop.
- **AI Used**: [DeepSeek-R1] [Code] - AuthService boilerplate.
```

---

## 6. Pull Request Checklist

Before submitting your PR, please verify the following:

- [ ] My code follows the project's style guidelines.
- [ ] I have performed a self-review of my code.
- [ ] I have added tests that prove my fix/feature works.
- [ ] New and existing tests pass locally.
- [ ] I have included an AI tag in the PR description if AI was used.
- [ ] I have not removed or altered the copyright/license headers in any file.

---

## 7. Review Process

1. Maintainers will review your PR within **3–5 business days**.
2. Feedback or change requests may be given; please respond promptly.
3. Once approved, a maintainer will merge your PR.
4. Your contribution will be credited in the release notes!
